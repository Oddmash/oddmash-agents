# Operator workspace

The existing root Vercel project serves both the worker and the compiled console assets. The webhook, advisory and queue entrypoints remain unchanged; console API routes use their own owner authentication. The pnpm workspace already supports independent applications and shared packages. From the root, run `pnpm install --frozen-lockfile --ignore-scripts`, `pnpm test` and `pnpm run typecheck`. Run the local API with `pnpm --filter @oddmash/agents-console dev:api` and the console with `pnpm --filter @oddmash/agents-console dev` in separate terminals; verify its build with `pnpm --filter @oddmash/agents-console build`. Internal packages use workspace dependencies and explicit exports for frontend and test consumers. Server-side function entrypoints and their transitive internal modules use explicit relative source imports so Vercel traces and transpiles the TypeScript files together rather than resolving source-only workspace package exports at runtime. They are private, source-only TypeScript contracts for the supported Node.js 24 worker and TypeScript-aware Vite build; they are not JavaScript library releases or supported external package APIs.

| Layer | Responsibility |
| --- | --- |
| apps/worker | GitHub webhook, queue, agent execution, release and policy enforcement |
| packages/operator-contract | Sanitized execution events, state projection, safe configuration contract |
| packages/operator-store | Bounded optional telemetry persistence, status projection and audited control storage |
| apps/console | Private authenticated operator UI, read-only status and bounded owner-only controls |

## Execution data

The worker emits its existing role-correlated lifecycle events. Events now optionally include the verified public repository and issue/PR number, and actual review phases when the corresponding work is reached. Private repository names and numbers are omitted. A returned handler is not evidence of review publication or approval. Projected jobs show returned, failed, queued, running, stale, skipped or published-only observations; stale is a UI inference based on elapsed time, not an agent verdict. Skips require an observed planning or scheduling decision and carry a fixed reason, not an inferred missing role. Successful public review or comment mutations record their kind, positive identifier and timestamp. A publication may be attached to an observed job without altering its lifecycle outcome, or be a standalone public observation where the parent delivery had no target. Private identifiers and review contents are not retained. New attempts replace older state. The console exposes repository groups and role summaries, separates stale observations from running and queued counts, and filters by observed repository, local activity day, role and state. Execution details show the latest visible attempt, reported queue/start/end timestamps, elapsed time only where the corresponding timing evidence exists, retained phase observations, the latest observed publication for each execution, and measured terminal usage. Running indicators and clocks stop when telemetry fails or the view is unmounted. The browser's local time zone is displayed. Unattributed private or unknown targets remain separate. All summaries are derived locally from the same bounded snapshot without extra API requests; a failed refresh labels any retained snapshot instead of implying it is live. Unknown fields and invalid identifiers are discarded; no model text, credential, request body or source code is part of the contract.

## Configuration

The worker exposes an internal projection function that selects explicit non-secret model and feature settings and whether required configuration is present. Configured is not proof that credentials work. No public route exposes the projection. The console uses the Hono status API and optional bounded shared storage. The separately authorized controls route can persist restrictions for future optional specialist participation and request/time limits; it cannot expand the deployment baseline or change review/approval/merge permissions. Revision conflicts fail closed and the audit list retains at most 50 changes. The console does not read worker environment variables or credentials directly. See the [console setup guide](../apps/console/README.md) for required GitHub OAuth and owner authentication variables, callback configuration, and optional worker/console storage credentials. Without storage, the console shows that telemetry is unconfigured.

## Observed model usage and release visibility

Terminal execution events may contain aggregate observed input and output tokens and counts of missing measurements. The status response derives role totals from distinct terminal attempts in the same bounded retained event list; there are no extra Redis commands or model requests. Calls not recorded by the provider instrumentation and older uninstrumented events are not counted. This is sample telemetry, not an invoice or budget enforcement. The console shows the reviewed build tag when supplied during production build and displays the effective opt-in flags and advisory request/time caps from the last settings snapshot, not credential or permission health.

## Bounded console resource budget

- Active status polling: up to 360 periodic requests per uninterrupted visible hour (10-second cadence), idle or retrying: up to 120 (30-second cadence). Hidden tabs abort in-flight status requests and stop polling; returning to a visible tab can trigger an additional immediate fetch. Each status request reads a single Redis pipeline containing two commands, for at most 720 or 240 read commands per visible hour per console instance, excluding settings-specific control operations. There is no model call from the console.
- The store retains at most 500 lifecycle and publication/skip events, expires inactive keys after seven days, and filters stale retained events. The decoder rejects JSON entries larger than 4096 characters. Each event write uses four Redis commands in one pipeline. Explicit skips and successful publications add writes only for observed outcomes; the coordinated role count and specialist inline finding cap bound these extra events without adding any console database reads. Observations are samples, not a complete audit history; older data may expire due to the count limit. The control audit stores at most 50 nonsecret change records separately.
- Local synthetic projection benchmark (Node 24, 500 distinct valid terminal events, 100 iterations): median 1.08 ms, p95 1.37 ms for event parsing plus job/usage projection; fixture JSON 173,393 bytes and projected jobs/usage JSON 168,336 bytes before transport compression. These are local illustrative measurements, not production CPU billing, provider quota or a guarantee of response size.
- Exact-head CI covers unauthorized status denial and the stable owner identity check. Live owner sign-in, persisted same-effective-value control save and restore were confirmed; an independent live non-owner account denial test is still required. The observed fleet state reports retained execution evidence and configured flags, not a service health or installation enrollment inventory.

# Central webhook deployment

The maintainer may opt all public Oddmash repositories into review by enabling the organization webhook. Private, internal, archived, external and draft targets are rejected. No contributor code is executed. Existing relay and scheduled review workflows remain unchanged until live webhook verification.

## Deployment

The unlinked Vercel project is `oddmash-reviewer` in team `qtaghdi`. GitHub Actions builds on reviewed main and uploads prebuilt output. Configure a protected GitHub environment named `production` restricted to main and store a scoped Vercel deployment token as environment secret `VERCEL_TOKEN`. No additional GitHub PAT is needed. Run Deploy Reviewer to Vercel manually once, then set the repository variable `VERCEL_DEPLOY_ENABLED=true` for automatic main deployments. No source or secrets are uploaded as CI artifacts.

The main-only deployment job synchronizes the existing GitHub organization secrets `REVIEWER_APP_PRIVATE_KEY` and `OPENAI_API_KEY` to this Vercel project's production environment as sensitive variables, and `REVIEWER_APP_ID` and `REVIEWER_APP_SLUG` from GitHub variables. Add a new strong random repository Actions secret named `REVIEWER_WEBHOOK_SECRET`, then set the same value as the GitHub App webhook secret. The sync enables review only when this secret is configured and `REVIEWER_APP_ENABLED=true` is set in GitHub. Optional `OPENAI_MODEL` defaults to the existing model. The deployment job verifies signed and unsigned ping behavior when a webhook secret exists.

In the Oddmash Reviewer GitHub App, enable the webhook at the project's production HTTPS URL plus `/api/github`, enter the identical webhook secret, and subscribe to Pull request and Check suite events. Keep Pull requests write, Checks read and Metadata read. The same app has Contents write for the separately gated merge module; review tokens are still Contents read. Verify actual installation permissions for label creation. Use a public production domain or explicitly configure protection so GitHub can reach this HMAC-authenticated endpoint; do not expose other deployments.

## Verification and migration

Check a signature-authenticated ping delivery, an ordinary public PR, a fork PR and completed checks. Verify review decisions, labels, and no review for private repositories. Existing review markers reduce duplicate reviews, but concurrent deliveries are not transactionally serialized. Background processing is bounded, not durable; redeliver or run a maintainer manual review after failures. Do not disable old workflows until live verification and a deduplication strategy are in place.

## Maintainer-only auto-merge pilot

The production deployment enables the separately gated merge policy for Kowrap, Oddmash UI, Interaction Inspector and Vertactics. Set the repository Actions variable `REVIEWER_AUTO_MERGE_ENABLED=false` and redeploy to stop it. Private repositories, organization policy, fork PRs and external contributors are excluded. Only `qtaghdi` (verified numeric account ID) PRs into protected main with a single standalone `Closes #N`, `Fixes #N` or `Resolves #N` line and a maintainer-authored open issue containing explicit acceptance criteria are eligible. Initial scope is ordinary Markdown documentation or newly added test files; source, configuration, existing tests, release and organizational policy changes remain manual. Missing evidence leaves the PR open. GitHub Actions verify must be required on the protected branch, current checks must pass, and exact-head independent app approval and validated acceptance evidence must exist. The merge module mints a repository-scoped Contents write token only after the checks and uses a head-SHA-guarded squash merge, without bypassing rules. Review-only behavior is unchanged for all ineligible PRs.

# Contributor PRs

The owner-only console includes open public Oddmash pull requests by external contributors. GitHub author association and user type distinguish external contributors from bots, members and collaborators; the configured owner is excluded by stable ID. Search is bounded to the 100 most recently updated public PRs before classification. Partial search results are labelled.

Each card shows repository, author, title, update time and draft status, separately from GitHub formal reviews, workflow observations and retained execution telemetry. On the four most recently updated external results, four additional public reads resolve the current PR head, verified Oddmash bot reviews (by stable account ID), matching PR workflow runs for that head, and verified Lead automation status comments. Review badges distinguish older revisions; a review is not a merge eligibility decision. The review page is capped at 100 chronological entries; incomplete evidence is labelled. The remaining cards show unavailable evidence.

Workflow action-required and waiting states are shown only when GitHub reports them. A fork run may lack a PR association; match its exact source repository, branch and head revision against the PR. Action-required may mean workflow approval or another manual action; the console links to GitHub for inspection rather than assuming the cause. Missing runs or failed reads are unknown, not evidence of successful checks or no review. A workflow failure badge is an observed run result, not the required-check aggregate.

An exact run failure is expanded with bounded job and step names from the latest attempt; raw logs are not read. A prior formal review or retained execution is not proof that a new workflow attempt or review has finished. Current workflow waiting/running states are prioritized, and historical retained executions are collapsed. Verified current-head Lead status comments show review processing failure or completion independently of formal review submissions.

A one-minute snapshot cache, four-card detail bound and rolling 50-request hourly instance budget limit anonymous requests. Twelve requests are reserved for search and optional reviews, comments and failure metadata are capped at 18 per hour; the remaining capacity is reserved for current-head detail and workflow observations. Successful search, PR detail and optional metadata are reused for up to five, two and five minutes respectively; workflow runs are reobserved after the one-minute interval. Search observation timestamps remain attached to cached search data. Refresh after the snapshot interval reobserves workflows within the available budget; while the page remains visible, running checks are refreshed after 65 seconds. If the budget or GitHub availability prevents a fresh search, cached PR identities are shown with evidence unavailable; the original observation time is preserved. Shared provider IP quotas may still limit evidence. All provider calls remain fixed-origin public read-only requests with a bounded timeout. No new credentials, workflow execution, approval or merge authority is introduced. State motion respects reduced-motion preferences.

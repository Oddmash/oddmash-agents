# Shared organization guidance efficiency

The optional REVIEWER_AUTHENTICATED_GUIDANCE_ENABLED=true flag uses the existing Lead installation to request a separate contents-read token scoped to the canonical public Oddmash/.github repository. The repository identity and returned permission are verified. No GitHub App permissions need to be expanded. If this token is unavailable the existing public read path remains in use. The token is reused for at most ten minutes within a warm process and concurrent issuance is coalesced. Never expose the token to the console.

Authenticated guidance reads use conditional HTTP requests when the same file has a cached ETag from the current token context; validators expire ten minutes after the full response and are never reused across token changes. A Not Modified response reuses the previously retrieved public content; a successful changed response replaces it. A denied, missing, malformed or unverifiable response is never replaced with stale cached data. The existing advisory fallback and exact-revision review requirements remain in force. Equivalent concurrent authenticated file reads are coalesced within the same token context. Failed reads clear the in-flight entry so a later attempt can retry. Anonymous reads do not use the cache.

The flag must be activated only after the maintainer verifies the installed app already has contents-read access to the verified public guidance repository. Inspect categorized request failures and quota metadata before and after activation; no permissions or deployment configuration change is included in this PR.

## Measurement

The worker emits `oddmash_github_request_counts` once per execution that uses the classified GitHub request helper, grouped by category, authenticated/anonymous, read/write, outcome and retry count. Correlation IDs identify the execution without including repository names, paths, headers or response bodies. Compare the organization-guidance counters and 403/429 failure classifications on equivalent workloads before and after the flag is enabled. These counts cover the helper, not every possible GitHub SDK call; not-modified responses are counted separately and are not proof of a reduced billed quota. Production observation on November 25, 2026, 22:14:51–22:44:51 KST (latest 100 classified telemetry records): 13 Lead executions reported organization-guidance reads. All 26 requests were authenticated, including 24 Not Modified responses and two successful full responses; no anonymous guidance reads were observed. The earlier baseline recorded 8 executions and 16 anonymous guidance requests, with no authenticated or Not Modified responses. Both samples had two classified requests per observed execution. This confirms authenticated conditional reuse and reduced full-response retrieval, not a lower request count, quota consumption or billed cost. The samples are bounded observations, not a controlled load test. A later burst at 22:47–22:53 KST produced repeated authenticated primary-rate-limit 403 responses in the other request category, with remaining quota zero and a reset at 23:13:16 KST. That confirms the broader quota problem remains unresolved; do not repeatedly request reviews before the reset. Measure the dominant request categories and duplicate lifecycle triggers in a later comparable healthy sample before claiming quota savings.

The deterministic shared-guidance tests cover ETag freshness, token-context separation, denial and invalid blobs, coalescing and failed in-flight cleanup. GitHub request tests cover bounded retry and quota deferral. Keep exact-head checks fresh; do not cache check-run evidence.
